# Chat UX Parity Plan (final) — transcript as the durable structured representation

Architecture (locked):

```
Native Engine → WorkReportData { telemetry: TurnTelemetry, context?: ContextTelemetry }
                  ├─ transcript.workReport        (canonical, versioned)
                  ├─ webview workReport message   (live turn)
                  └─ legacy markdown fallback     (old transcripts ONLY — never parsed by new UI)
Live rendering == replay rendering — same ResultCard(report) path.
```

## Token semantics (authoritative definitions)

**`TurnTelemetry.inputTokens`** = accumulated provider-reported input tokens across ALL model calls of the entire turn (planner + executor + judges + continuations + verify-fix rounds). This is turn COST accounting — what the footer shows as "X in · Y out", what the ResultCard stats row shows. Monotonically grows with each call.

**`ContextTelemetry.contextTokens`** = the actual context size of the MOST RECENT model request (conversation + retained history + tool output + system prompt as actually sent). This is window PRESSURE state — only the context chip consumes it: `percent = contextTokens / contextWindow × 100` where `contextWindow` is the SERVING model's window (never the selected model's — failover changes it).

The two numbers answer different questions and are never mixed: "how much did this turn cost" (telemetry) vs "how full is the context right now" (context).

## Step 1 — Shared types at a dependency-neutral boundary

New `src/shared/workReport.ts` — host/runtime AND webview import from `src/shared/` only; the webview never imports agent-runtime modules:

```ts
export interface TurnTelemetry {      // THE accounting object — status line, footer, ResultCard, replay all read it
  model: string;                      // "provider/modelId" or "unknown" — required, deterministic rendering
  taskKind: TaskKind;
  inputTokens: number;                // accumulated provider-reported input tokens across the entire turn
  outputTokens: number;               // accumulated output tokens across the entire turn
  toolCalls: number; thoughts: number; failovers: number; elapsedMs: number;
}
export interface ContextTelemetry {   // request/window pressure state — NOT turn accounting
  contextTokens: number;              // context size of the most recent model request
  contextWindow: number;              // serving model's window
  percent: number;
  // future: breakdown { system, retained, user, tools }
}
export interface WorkReportData {
  version: 1;                         // persisted — readers switch on it
  verifyOutcome: 'verified' | 'failed' | 'unverified' | 'changes-only';
  verifyCmd?: string;
  fixRounds: number;
  changedFiles: Array<{ path: string; status: 'A' | 'M' | 'D' }>;
  toolTally: Array<{ name: string; count: number }>;
  stopReason: string;
  telemetry: TurnTelemetry;           // nested — no duplicated fields anywhere
  context?: ContextTelemetry;
  checkpointId?: string;
}
```

## Step 2 — Native engine produces WorkReportData

`loop.ts` report block becomes a pure builder → `WorkReportData | undefined`. `elapsedMs` from turn start; `inputTokens/outputTokens` accumulated per-call from provider-reported step usage; `model` from the serving platform/model (`'unknown'` fallback); `context` snapshot from the final request's fitted messages + serving model window. Existing markdown strings become `renderLegacyMarkdown(report)`.

## Step 3 — Persist canonically; host owns fan-out

`AgentResult.workReport?`; `chatViewProvider` turn lifecycle (NOT a callback) writes `s.transcript[i].workReport` and appends legacy markdown to `.text` marked `// LEGACY TRANSCRIPT SERIALIZATION — remove after the minimum supported transcript migration window.`

**Checkpoint contract (documented, plumbing unchanged):** `checkpoints.begin(requestId)` is turn-scoped; `record()` snapshots pre-edit content at write time; a later turn cannot overwrite turn N's snapshot. `workReport.checkpointId` = its own turn's requestId; replay clicks always diff against that immutable baseline.

## Step 4 — Webview message

`{ type:'workReport', requestId, report }` posted with `assistantMessage` (text WITHOUT report markdown — host strips with the same builder it appended with). Webview stores on the live turn target.

## Step 5 — ResultCard live rendering

`media/src/ui/components/ResultCard.ts` — `ResultCard(report)` receives the whole object; reads only `report.telemetry.*` / `report.context?.percent`. Header status badge + verify-cmd chip + fix rounds + elapsed; files with `.cp-badge` A/M/D + click → `diffCheckpointFile(report.checkpointId, path)`; stats from `telemetry`; tally `<details>`.

## Step 6 — Replay, same path (wired now)

`renderAssistantStatic` mounts `ResultCard(entry.workReport)`; absent → legacy markdown renders as before. Old transcript → legacy renderer → UI; new data NEVER round-trips through markdown/regex.

## Step 7 — Legacy fallback only

`renderLegacyMarkdown` + strip helper share one implementation so emit/strip can't diverge.

## Step 8 — unifiedDiff: pure, UI-independent

`media/src/format/unifiedDiff.ts`: `unifiedDiff(oldText, newText, { oldLabel, newLabel, context = 3 }) → string`. Line LCS → hunks. CRLF/LF normalized before diffing. Moved blocks = deterministic delete+add hunks (no semantic move detection). Tests cover exact hunks, pure adds/deletes, CRLF, move determinism.

## Step 9 — ToolCard diff2html integration, named thresholds

```ts
const INLINE_DIFF_MAX_CHANGED_LINES = 400;
const INLINE_DIFF_MAX_BYTES = 50 * 1024;
const DIFF_PREVIEW_MAX_CHANGED_LINES = 2000;
```
Boundary-tested (399→inline, 400→collapsed, 1999→collapsed, 2000→summary). ToolCard consumes unified-diff strings only. `createFile` tabs and EditGate native approval diff unchanged.

## Step 10 — Telemetry polish (single source)

Failover suffix + footer `⟳ N` from `telemetry.failovers`; work-summary tokens from `telemetry`; taskKind pill. No recomputation.

## Step 11 — Composer

Dynamic per-mode placeholder; context chip from `context.percent` (serving model's window; amber > 70%); serving-model state machine `selected → serving:A → (failover) serving:B → selected`, reset in the turn lifecycle's `finally`; empty-input hint row; remove dead `checkpoint.css` link.

## Step 12 — Regression

`unifiedDiff.e2e.ts` (+ boundaries), `workReport.e2e.ts` (builder + legacy round-trip), `tiermuxWeb.e2e.ts`, core/verify-gate/reanchor/step-routing/self-correct + typecheck + `npm run build`.
