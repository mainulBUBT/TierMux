# TierMux Quality Parity Plan (revised) — ExecutionProfile-centered

Incorporates review: (1) a single `ExecutionProfile` resolution instead of scattered rank checks, (2) execution order re-sequenced so **readFile/tool surface** and **context retention** land first — the two highest-value changes; diet/limits make the system efficient and predictable around them.

## Phase 0 — ExecutionProfile (the spine, lands with Phase 1)

New `src/agent/executionProfile.ts`:

```ts
export interface ExecutionProfile {
  modelRank: number;              // catalog intelligenceRank (lower = smarter); 5 = unknown
  strong: boolean;                // rank <= 2
  outputTokenLimit: number | null; // catalog field (Phase 4 populates; null = unknown)
  contextWindow: number;          // resolved (fallback 32768)
  useWeakModelScaffolding: boolean; // rank >= 3 (drives REACT scaffold + behavior.md weak sections)
  useAnswerJudge: boolean;        // !strong (Phase 5 wires the judge skip)
  pruneTarget: number;            // 85% of contextWindow, clamped [12k, 120k] (Phase 2 consumes)
}

export function resolveExecutionProfile(model: CatalogModel | undefined): ExecutionProfile
```

- Resolved ONCE per turn in `runTurn` right after taskKind classification (from `router.peekTopSelection(taskKind)?.model`), threaded where needed; `Router.route()` uses the same helper for its max_tokens decision so loop and router never disagree.
- Each later phase POPULATES/CONSUMES fields instead of adding its own rank check: prune (2.1), STRONG_PROFILE_SKIP (3.4), output limit (4.2), judge skip (5.2). Today's scattered `isWeakExecutor`/`isStrongExecutor`/`WEAK_EXECUTOR_RANK` checks migrate onto the profile.

## Phase 1 — Tools as the instruction surface + line-addressable readFile [P0, very high, low risk]

1.1 **readFile output format** (`src/agent/core/tools/filesystem/read.ts`): `cat -n` padded line numbers + `<file path="...">…</file>` wrapper per file; keep paging/offset notice. Enables accurate `file:line` citation AND exact `editFile` search-string derivation (today's un-numbered content is a real edit-hunk-mismatch source).

1.2 **Instruction-rich tool descriptions** (rules move OUT of the system prompt INTO the tools that execute them — Claude Code's core technique):
- `grep`: scope-narrowing rule (pass glob/path first; whole-workspace last resort), result shape `file:line:text`, match-cap note.
- `glob`/`listDir`: usage rules (glob over shell-`ls`; listDir = one level).
- `todowrite`: the todo discipline (exactly one in_progress, complete immediately, never finish with pending) — currently buried in AGENT_MODE_TAIL; array param gets `.describe()`.
- `editFile`: "fails if the file wasn't read this turn" (matches the existing permission ledger).
- `delegate`/`implementPipeline`: their guidance blocks migrate from AGENT_MODE_TAIL into their descriptions.

## Phase 2 — Context retention [P0-equivalent, very high, medium risk]

2.1 **Prune threshold 40% → 85%** of contextWindow, clamped [12k, 120k] — via `profile.pruneTarget` (replaces the 0.4 formula in `adaptivePruneAtTokens`; explicit user setting still wins, 0 still disables). The current 40% blanking is the single biggest "model forgot the evidence" quality killer; OpenCode compacts at ~90% and the existing cascade (blank → prune reasoning → evict → re-anchor) already handles real pressure.

2.2 **Auto-condense between turns**: when projected history > 80% of profile.contextWindow and ≥16 messages → run existing `condenseHistory` once (bounded, once per N turns; manual /compact unchanged).

2.3 **Tagged context injections**: re-anchor digest, budget nudges, trimmed markers wrapped in `<tiermux-context>…</tiermux-context>`, semantics defined once in the system prompt (harness-injected status, not user speech) — the `<system-reminder>` pattern, wire-agnostic.

## Phase 3 — Prompt diet + stable prefix [P0, high, medium risk]

3.1 Slim AGENT_MODE_TAIL (~6.9K → ~2.5K): delete sections migrated in Phase 1 (todo workflow, delegate, implementPipeline, web-E2E recipe); keep mode definition, autonomy contract, structured finish, grounding, tool-call fallback dialect (once).
3.2 Slim behavior.md (9.2K → ~5K): keep top-3 rules, answer style + `<example>` few-shots, citation format; compress debugging/planning/UI sections to one line each.
3.3 **Cache-boundary assembly** (buildSystemPrompt): stable core (scaffolding + modeTail) → instructions (rules/memory/skills) → volatile last (todayLine + findings). Stable prefix stays byte-identical within a session → OpenRouter/DeepSeek exact-prefix caching engages (date line currently sits mid-prompt).
3.4 **Profile-driven prompt sections**: `useWeakModelScaffolding === false` drops weak-model-only sections — the single conditional cut (no per-provider forks; opencode's own maintainers called those unjustified drift, and GPT-5-Codex ships a shorter prompt).

## Phase 4 — Output limits + wire hygiene [P0, high, low risk]

4.1 Add `outputTokenLimit: number | null` to CatalogModel + catalog.ts parsing; curate top ~30 free models from models.dev (mostly 8192–32768).
4.2 Router max_tokens via the shared profile helper: `min(model.outputTokenLimit ?? ∞, supportsReasoning ? 16384 : 8192)` when unset — raises today's 4096 floor (mid-answer truncation → up-to-4 continuation stitches) while never exceeding the real cap; fixes the sentinel mismatch (reserves 4096, sends 8192).
4.3 Hygiene: normalize assistant `content: null` → `""` when tool_calls present (gateway compatibility). Keep as-is: no temperature (safest), no `strict:true` (400-risk on all-required endpoints; zod schemas already emit additionalProperties:false + required), no `parallel_tool_calls` except NVIDIA's existing case.

## Phase 5 — Continuity + judge optimization [P1, medium-high, medium risk]

5.1 **Session model lock**: per-chat lock makes the pinned model authoritative — Auto keeps it while healthy + quota remains; rotation/failover only on real failure (OpenCode-style per-session consistency).
5.2 **Judge skip** via `profile.useAnswerJudge === false` (strong executors): skip judgeFulfillment/compareAnswers + quality-escalation re-run — strong models self-correct in-loop; the cascade mostly adds latency and context pollution for them.

## Tests (esbuild e2e pattern)
- `executionProfile.e2e.ts` — resolution defaults, strong/weak boundaries, unknown-model fallback; loop/router agree on max_tokens.
- `readFormat.e2e.ts` — cat -n + `<file>` tags + offset notice + batch separators.
- `pruneThreshold.e2e.ts` — 85% formula, clamps, user override, 0-disables.
- `promptDiet.e2e.ts` — agent system prompt < 12K chars; stable prefix byte-identical across builds in-session; volatile parts last.
- `outputLimit.e2e.ts` — catalog parse + min() math + sentinel consistency.
- Update affected existing suites (edit-match, reanchor, core) for the readFile format change.
- Regression per phase: typecheck + core/scoring/step-routing/verify-gate/hedge/condense-split.

## Execution order
0+1 → 2 → 3 → 4 → 5 (readFile/tools first, context retention second — per review; diet and limits wrap around them; profile grows one field per phase, no scattered rank checks anywhere).

## Not adopting
Per-provider prompt forks (drift), `strict:true` schemas (endpoint 400-risk), native adapters (out of scope — all providers OpenAI-compat), dsh plugin architecture (churn, no quality payoff).
