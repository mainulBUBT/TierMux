# Modern agent-wise composer redesign

Redesign the chat prompt-input toolbar (agent mode, model, and other controls) into a modern, cleanly organized single-row layout, built as proper UI components following the project's existing factory-function + `tm-` CSS + design-token architecture. **No protocol changes** — every existing behavior (per-session composer state, serving-model indicator, plan-executing pill state, host `setMode` message, `sendMessage` payload) is preserved.

## Target UI

```
┌────────────────────────────────────────────────┐
│ Ask anything about this workspace…             │
│ ────────────────────────────────────────────── │
│ [⚡ Agent ▾] [◈ Auto ▾] [＋]  ·  [⚡][ℹ] [➤]  │
└────────────────────────────────────────────────┘
```

- **Agent picker** (primary, tinted per mode) → popover of rich agent cards: icon tile, name, description, capability chips (`read-only` / `edits after approval` / `full access`), check on selected.
- **Model picker** → popover with search, **reasoning-effort segmented control (Off/Low/Med/High/Max, moved here from the toolbar)**, an "Auto — smart routing" row, and provider-grouped model rows with T/V/R capability chips + status tags (unavailable/slow/off) + selected check.
- Right group unchanged in function: auto-approve, tips, send. Reasoning `<select>` is removed from the toolbar.

## New files

1. **`media/src/ui/primitives/Popover.ts`** — reusable anchored popover: `createPopover({ anchor, content, onOpen, onClose })` → `{ el, open, close, toggle, isOpen }`. Centralizes the currently-duplicated open/close logic: click-away, Escape, window blur, `visibilitychange`, plus a module-level registry so opening one popover closes the other (autocomplete popup keeps its own separate handling).
2. **`media/src/ui/components/AgentPicker.ts`** — `createAgentPicker({ modes, value, onChange })` → `{ el, setValue, setExecuting }`. Takes a `modes` array (value/label/icon/desc/caps) so `MODES` stays main.ts-owned; renders trigger + card popover; `setExecuting(on)` reproduces the visual-only "executing plan" pill state.
3. **`media/src/ui/components/ModelPicker.ts`** — `createModelPicker({ value, onChange, onReasoningChange, onStatus })` → `{ el, setValue, setOptions, setServing, setReasoning }`. Searchable grouped list (filter hides group headers, as today), reasoning segmented control, Auto row, caps chips + status tags with the existing tooltips, selected check (reuses `ICON.check`). `setServing(label|null)` drives the existing serving/failover indicator on the trigger.
4. **`media/styles/components/composer.css`** — all new styles, `tm-` prefixed, built on `--tm-*` tokens / `--vscode-*` theme vars: `.tm-popover` shared chrome, `.tm-agent-*` (per-mode tint variants), `.tm-model-*` (search, reasoning segment, group headers, rows, tags), plus toolbar polish (subtle divider between control cluster and action cluster, modernized gaps, responsive rules <300px keeping agent/model/send visible).

## Behavior explicitly preserved
- `sendMessage` wire payload (mode/model/reasoningEffort) and all host messages — zero changes in `src/messages.ts`.
- Per-session draft/model/mode/reasoning/attachments restore; pinned-model-not-in-enabled-set notice; reasoning forced `off` on non-reasoning pinned models (segmented control disables with a note); plan-executing pill keyed by requestId; host `setMode` on plan execution.
