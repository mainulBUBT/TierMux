## Goal
When the user asks TierMux to add/test a web feature ("add order"), the agent verifies its work END-TO-END by itself: detect the project's stack, start the dev server via bash (backgrounded), exercise the new pages/APIs over HTTP, confirm the result, and clean up — no "open the browser and check yourself". 

## What exists / what's missing
- `runCommand` can start servers, but a foreground server blocks until timeout — the background (`nohup … &` + pid file) pattern is never taught, so agents don't do this.
- `fetchUrl` is built for public-document extraction (markdown readability chain, tagged as external content) — wrong tool for hitting `http://127.0.0.1:8090`: no status codes, no redirect chain, mangles app HTML, and JS-rendered SPA pages come back empty.
- No prompt guidance for stack-aware end-to-end verification; a URL check doesn't count as verification in the honesty backstop (`VERIFY_TOOLS` = runCommand/getDiagnostics only).

## Changes

### 1. New `checkUrl` tool — `src/agent/core/tools/network/checkUrl.ts`
A verification-first HTTP checker (GET/HEAD), localhost-first:
- `{ url, expectStatus?, marker?, render? }`
- Plain `fetch` (8s timeout, no-cache): returns **status, content-type, final URL after redirects, size**, and content — JSON pretty-printed when JSON, else `<title>` + tag-stripped text (~4K) or raw head (~2K).
- `marker: "Order placed"` → explicit `MARKER FOUND / NOT FOUND` verdict line; `expectStatus: 200` → pass/fail line. Deterministic signals the model (and the Work Report) can cite.
- `render: true` for JS-heavy apps: dump the RENDERED DOM via headless Chrome (`CHROME_PATH` → macOS app path → linux chrome/chromium; `--headless=new --dump-dom --virtual-time-budget=5000`), parsed the same way; clean fallback message when no Chrome exists.
- Localhost/127.0.0.1 responses are the user's own app — not wrapped in the external-content safety tag; non-localhost responses ARE tagged (same reasoning as `fetchUrl`).
- Registered in all three modes' tool sets (GET is read-only); NOT in `MUTATING_TOOLS` (auto-approves like `fetchUrl`). Form/POST/API-mutation checks stay in `runCommand` via `curl -X POST`, where the existing approval gate covers them.

### 2. Verification accounting — `loop.ts`
Add `checkUrl` to `VERIFY_TOOLS` — a real HTTP check of the changed behavior counts as external verification for the honesty backstop / Work Report status.

### 3. Stack-aware test workflow in the prompt — `AGENT_MODE_TAIL` (promptBuilder.ts)
New section "Testing web features end-to-end":
1. Detect the stack (artisan/composer → `php artisan serve --port=…`; package.json `dev`/`start` scripts → `npm run dev -- --port …`; vite/next patterns; docker compose if present).
2. Start it BACKGROUND with a fixed port and pid file: `nohup php artisan serve --port=8090 > /tmp/tiermux-dev.log 2>&1 & echo $! > /tmp/tiermux-dev.pid` (returns immediately — never block on a foreground server).
3. Poll readiness with `checkUrl` (a couple of retries), then exercise the changed feature: pages via `checkUrl` (with `marker`), mutations via `curl -X POST` through `runCommand`.
4. ALWAYS clean up: `kill $(cat /tmp/tiermux-dev.pid)` — even on failure.
5. The end-to-end result feeds the structured finish (verified via live URL vs untested).

### 4. Test — new `scripts/checkUrl.e2e.ts` (+ package.json wiring)
Spin a real ephemeral local http server (node `http`) serving: an HTML page, a JSON endpoint, a 404, and a redirect. Assert: status/content-type/size reported; `marker` found and not-found verdicts; `expectStatus` pass/fail; JSON pretty-printed; localhost output NOT external-tagged; `render:true` returns either real rendered DOM or the clean no-Chrome fallback. Then typecheck/build/regression sweep (core, self-correct, verify-gate, mode-guard — tool-set changes touch those).

## Out of scope (deliberate)
Full browser automation (clicks/forms/screenshots via Playwright) — heavy dependency for an extension; `render:true`'s headless-Chrome DOM dump covers "did the SPA actually render my feature" for v1. POST stays in the approval-gated shell.
