# TierMux v3 — Policy Layer over AI SDK (Corrected)

## 5 corrections applied

1. **`repairToolCall` is not "always model self-correction."** Verified at `node_modules/ai/dist/index.js:3861-3891` — SDK calls `repairToolCall` **once** per malformed call. If the returned call is also invalid, the SDK falls through to `index.js:3893-3910` which **forwards the unparseable call to `execute()` anyway** with `invalid: true`. The plan now treats this as Path A (malformed) and budgets repairs with a per-turn counter; tools also handle unparseable input defensively.
2. **Policy priority: `alwaysDeny → alwaysAllow → read-only → mode → ask`.** Full-auto cannot bypass `alwaysDeny`. See §3.
3. **`stopWhen: [stepCountIs(50)]` only in v3.0.** No `taskComplete` tool. Natural model termination is enough.
4. **Minimal `prepareStep`: just token-budget compaction.** No re-anchor, no collapseRepeat, no watchdog.
5. **Execution order: POC + 10 foundation scenarios first, mass delete last.** Agent loop is built and validated before any file is removed. The 10 scenarios are the gate.

### Two failure paths, designed separately

- **Path A (malformed tool call)**: SDK's `parseToolCall` fails → `repairToolCall` is invoked ONCE. If the repair returns null or produces another invalid call, the SDK wraps the original with `invalid: true` and forwards to `execute()`. TierMux's tools handle this with a top-of-`execute()` safe-parse and return `{ error: string }` on unparseable input. The wrapper's repair counter caps this at 3 per turn.
- **Path B (tool execution error)**: SDK's `executeToolCall` catches throws at `ai/dist/index.js:3042-3065` and wraps as `{ type: 'tool-error', error }`. The loop continues, the model sees the error in the next turn and decides what to do. **No custom retry logic needed** — AI SDK already does this.

## 1. Thin wrapper (~250 LOC)

**File:** `src/agent/agent.ts` (NEW)

```ts
import { streamText, stepCountIs, type ModelMessage, type ToolSet, type LanguageModel } from 'ai';
import { createRouterProvider } from './core/routerProvider';
import { buildToolSet } from './core/tools';
import { resolvePolicy } from '../permissions/policy';
import { selectModel } from '../router/picker';
import { composeSystemPrompt } from '../context/system';
import { loadHistory, saveTurn } from '../session/store';
import { makeRepairViaModelSelfCorrection } from './core/repair';

export async function runAgent(opts: AgentOpts): Promise<void> {
  const history = await loadHistory(opts.sessionId);
  const messages: ModelMessage[] = [...history, { role: 'user', content: opts.prompt }];
  const tools: ToolSet = await buildToolSet(opts.mode, opts);
  const model: LanguageModel = createRouterProvider({
    select: (msgs) => selectModel(msgs, opts),
    onModel: opts.onModel,
  });
  const repair = makeRepairViaModelSelfCorrection({ model, signal: opts.signal });

  const result = streamText({
    model,
    system: await composeSystemPrompt(opts),
    messages,
    tools,
    toolApproval: (call) => resolvePolicy(call, opts),
    repairToolCall: repair,
    prepareStep: ({ messages }) => compactIfNeeded(messages, opts),
    stopWhen: [stepCountIs(50)],                                    // v3.0: nothing else
    abortSignal: opts.signal,
    maxRetries: 1,
    onChunk: ({ chunk }) => { if (chunk.type === 'text-delta') opts.onChunk?.(chunk.text); },
    onStepEnd: (step) => { /* forward tool events */ },
    onError: ({ error }) => opts.onError?.(error),
    onEnd: async ({ steps, totalUsage, finishReason }) => {
      await saveTurn(opts.sessionId, { messages: steps.flatMap(s => s.responseMessages ?? []), usage: totalUsage });
      opts.onDone?.({ finishReason, text: steps.at(-1)?.text ?? '' });
    },
  });
  await result.consumeStream();
}
```

## 2. Self-correction with budget (~100 LOC)

**File:** `src/agent/core/repair.ts` (NEW)

```ts
const REPAIR_BUDGET_PER_TURN = 3;

export function makeRepairViaModelSelfCorrection(ctx: { model: LanguageModel; signal?: AbortSignal }) {
  let count = 0;
  return async function repairViaModelSelfCorrection({ toolCall, tools, inputSchema, error, messages }) {
    if (count >= REPAIR_BUDGET_PER_TURN) {
      diagLog('repair.budget', `exceeded ${REPAIR_BUDGET_PER_TURN} repairs in turn, returning null`);
      return null;       // SDK falls through to invalid-call path; the tool's execute() will receive the bad input
    }
    count++;
    const toolList = Object.keys(tools).map(n => `- ${n}`).join('\n');
    const isNoSuch = NoSuchToolError.isInstance(error);
    const isInvalid = InvalidToolInputError.isInstance(error);

    const correctionMessages: ModelMessage[] = [
      ...messages.slice(0, -1),
      { role: 'user', content: [{
          type: 'text',
          text:
            `Your previous tool call was malformed.\n\n` +
            `Tool called: ${toolCall.toolName}\n` +
            `Tool input: ${JSON.stringify(toolCall.input)}\n` +
            `Error: ${error.message}\n\n` +
            (isNoSuch
              ? `This tool does not exist. Available tools:\n${toolList}\n\nPick the correct tool name and emit ONE valid tool call. No prose.`
              : isInvalid
                ? `Required JSON Schema for "${toolCall.toolName}":\n${JSON.stringify(await inputSchema({ toolName: toolCall.toolName }))}\n\nEmit ONE valid tool call. No prose.`
                : `Unknown error. Try again with ONE valid tool call.`)
        }] },
    ];

    const fix = await streamText({
      model: ctx.model,
      messages: correctionMessages,
      tools,
      stopWhen: [hasToolCall('*'), stepCountIs(1)],
      abortSignal: ctx.signal,
    });
    const tc = (await fix.steps).flatMap(s => s.toolCalls ?? [])[0];
    return tc ?? null;
  };
}
```

**Constraint:** `repairToolCall` is called once per malformed call by the SDK. The `count` budget prevents the model from re-emitting the same broken call indefinitely. The recursive `streamText` is itself bounded.

## 3. Permission policy with explicit priority (~250 LOC)

**File:** `src/permissions/policy.ts` (NEW)

```ts
export async function resolvePolicy(call, opts): Promise<ToolApprovalStatus> {
  const config = await loadPolicy(opts.sessionId);

  // Priority 1: alwaysDeny ALWAYS wins — even in full-auto.
  if (config.alwaysDeny.has(call.toolName)) return { type: 'denied', reason: `tool "${call.toolName}" is in alwaysDeny list` };

  // Priority 2: explicit allow short-circuits everything except deny.
  if (config.alwaysAllow.has(call.toolName)) return { type: 'approved' };

  // Priority 3: read-only tools always approved.
  if (READ_ONLY_TOOLS.has(call.toolName)) return { type: 'approved' };

  // Priority 4: mode policy
  if (config.mode === 'full-auto') return { type: 'approved' };
  if (config.mode === 'auto') {
    if (config.autoModeAllowlist.has(call.toolName) || READ_ONLY_TOOLS.has(call.toolName)) return { type: 'approved' };
    // fall through to ask
  }

  // Priority 5: ask the user
  const d = await opts.requestApproval?.({ tool: call.toolName, input: call.input });
  if (d === 'allow-always') { config.alwaysAllow.add(call.toolName); await savePolicy(opts.sessionId, config); }
  return d === 'allow' || d === 'allow-always' ? { type: 'approved' } : { type: 'denied', reason: 'user denied' };
}
```

`READ_ONLY_TOOLS` (single source of truth, used here and in `buildToolSet`): `readFile`, `listDir`, `glob`, `grep`, `getDiagnostics`, `getSymbolGraph`, `getDependencyTree`, `webSearch`, `fetchUrl`, `showTodo`, `askUser`, `recallNotes`, `checkPlan`.

## 4. Tools (20) — `tool({...})` form, every `execute()` is exception-safe

```ts
// src/agent/core/tools/filesystem/read.ts
import { tool } from 'ai';
import { z } from 'zod';
import * as vscode from 'vscode';

export const readFile = tool({
  description: 'Read the contents of a file in the workspace.',
  inputSchema: z.object({
    path: z.string().describe('Workspace-relative path'),
    startLine: z.number().int().nonnegative().optional(),
    endLine: z.number().int().positive().optional(),
  }),
  execute: async ({ path, startLine, endLine }, { abortSignal }) => {
    // Path A defense: SDK may hand us unparseable input via the invalid-call fallback
    // (ai/dist/index.js:3893-3910). We never throw out of execute() — we return a
    // structured error so the model can see it in the next turn and self-correct.
    try {
      const bytes = await vscode.workspace.fs.readFile(vscode.Uri.file(resolveWorkspacePath(path)));
      const text = Buffer.from(bytes).toString('utf8');
      return (startLine || endLine) ? text.split('\n').slice(startLine ?? 0, endLine ?? Infinity).join('\n') : text;
    } catch (e) {
      return { error: e instanceof Error ? e.message : String(e) };
    }
  },
});
```

```ts
export async function compactIfNeeded(messages, opts): Promise<{ messages?: ModelMessage[] }> {
  const budget = opts.contextWindowTokens ?? 0;
  if (budget <= 0 || estimateTokens(messages) < budget * 0.8) return {};
  const compacted = [];
  for (let i = 0; i < messages.length; i++) {
    const m = messages[i];
    if (m.role === 'tool' && i < messages.length / 2) {
      compacted.push({ role: 'tool', content: [{ type: 'tool-result', toolCallId: (m.content[0] as any).toolCallId, toolName: (m.content[0] as any).toolName, output: { type: 'text', value: '(result omitted — see earlier in conversation)' } }] });
    } else {
      compacted.push(m);
    }
  }
  return { messages: compacted };
}
```

## 10. Why this is right

- **Verified against `ai@7.0.58` source**: every SDK assumption is anchored to specific lines.
- **Two failure paths, designed separately**: Path A (malformed) is handled by `repairToolCall` + budget + defensive tools. Path B (execute error) is handled by AI SDK's built-in `tool-error` wrapping — no custom retry logic.
- **Explicit policy priority**: `alwaysDeny > alwaysAllow > read-only > mode > ask`. Full-auto cannot bypass alwaysDeny.
- **Minimal `prepareStep`**: only the token-budget compaction. Nothing else in v3.0.
- **POC-first execution order**: the agent loop is built and validated against 10 scenarios before any mass delete. If a scenario reveals an SDK gotcha, the plan adapts — nothing is destroyed.
- **Net ~−8,100 LOC** (more aggressive than previous plan's −4,200): `toolArgs.ts` (677) + `loop.ts` (1,358) + 8 `router/*` files (4,500) + 7 `edits/*` files (2,000) + 6 `core/tools/*` glue (400) + 4 `agent/*` files (1,500) + 2 `core/*` glue (900) + others (~600).

### Approve ≠ blanket approval (invariant)
Plan approval শুধু `Plan → Agent` mode transition করে; future tool calls auto-allow হয় না। Agent mode-এর নিজস্ব policy (`alwaysDeny > alwaysAllow > read-only > mode > ask`) প্রতিটা tool call-এ apply হবে।

- `alwaysDeny` items — Plan mode-এ blocked ছিল, Agent-এও blocked
- `alwaysAllow` items — যদি user "Always allow" click করে specific tool-এ, তাহলে persist হবে
- বাকি সব — Agent mode-এর `ask` / `auto` / `full-auto` setting অনুযায়ী gate-এ যাবে

`pendingPlanUser` / `pendingClarify`-এর plan-specific branch গুলো remove — Ask mode-এর flow-এ merge হবে (clarifying questions are mode-agnostic)।

### Why this is right
- v3 plan-এ `planRunner` already delete-list-এ ছিল — এটা এর continuation
- `planStructurer` + `Plan.ts` parser model output থেকে structure recover করার চেষ্টা করত — fragile, weak model-এ ভাঙত
- Markdown output convention model-ই follow করবে — কোনো regex parser নেই
- Execution Plan mode-এ possible নয় (edit/deny), তাই approve-এর পর সব re-engage

### Architectural invariants (locked — do not bypass)
- **Tool visibility (canonical for static mode denials):** Permission policy filters the tool registry before `streamText`; denied tools are not exposed to the model. Plan mode-এ `edit`/`write`/`delete` tool-ই না থাকলে model physically call করতে পারবে না — runtime check-এর চেয়ে clean ও reliable। `buildToolSet(mode)` drops edit/write/delete in plan mode; `runCommand` stays in the registry (gated by `toolApproval` → ask, not by the registry filter).
- **Approval (canonical for per-call policy):** Use AI SDK's native `toolApproval` flow for the `alwaysDeny > alwaysAllow > read-only > mode > ask` chain. Static mode denials are registry-filtered; everything else — `alwaysDeny`/`alwaysAllow`/`ask`, including plan mode's `runCommand` ask — is enforced at runtime by `toolApproval`. Custom Deferred/permission state machine বানানো যাবে না — যতক্ষণ না AI SDK naturally stream pause/resume support করে। SDK যা দেয় তাই use, নিজে কিছু বানিও না।

### Out of scope (re-affirm)
- `.opencode/plans/` plan file persistence — v3-তে add হচ্ছে না, v3.1-এ defer
- `plan_enter` / `plan_exit` meta-tools — `setMode('agent')` direct swap যথেষ্ট
- Runtime deny via a custom permission state machine — out of scope. Canonical enforcement is exactly two paths: (a) registry filter for static mode denials (edit/delete in plan mode) + (b) native `toolApproval` for per-call policy. Don't build a deny path outside these two.
- `findLast` wildcard rule eval — TierMux-এর fixed priority (`alwaysDeny > alwaysAllow > read-only > mode > ask`) sufficient

## 15. Model selection & failover — final architecture (v3)

Task routing + free-model fallback chain + per-model cooldown + one-shot quality recovery.
No Cursor-style ML router — a static, readable table is enough (Cursor's own routing is
proprietary/data-driven; replicating it is out of scope).

### Flow
```
User request
   ↓
Task classifier
   ↓
Free-model candidate pool
   ↓
Rank / order
   ↓
Model A
 ├─ success                         → DONE
 ├─ 429/5xx/timeout/network         → cooldown → Model B
 └─ empty/broken answer (1 recovery)→ still bad → Model B
                                      ↓
                                  Model C
                                      ↓
                                  Model D
```
The same `messages` are re-sent to B/C/D, so a model change never loses conversation context.

### Candidate pool
`TASK_ROUTING` (picker.ts) holds the per-task-kind ordered chain of free/usable models, e.g.
`coding: ['groq::model-a', 'cerebras::model-b', 'openrouter::model-c', 'nvidia::model-d']`.
`selectModel` pads the chain with every other usable enabled model so a pinned model is never
a single point of failure (the old "pinned = 1 candidate, no failover" bug). All entries are
free/usable — keyless platforms or ones with a stored key.

### Per-model cooldown (minimal health)
```ts
modelHealth = { failures: number; cooldownUntil: number }
// 429 → 30s · 429 again → 2m (exponential, capped) · 5xx/timeout → cooldown · success → reset
```
In-memory module-level `Map` in picker.ts. `recordOutcome(platform, modelId, ok)` is called by
routerProvider after each candidate attempt; `selectModel` skips models still in cooldown
(except the pinned one). This RE-INTRODUCES a lightweight cooldown that the earlier
"delete the Router" pass had dropped — the rest of the Router (scoring / hedging / session-pin /
circuit-breaker) stays deleted. OmniRoute's connection cooldown + provider circuit breaker is
the same class of resilience; we keep only the minimal version.

### Quality recovery
routerProvider's `doStream`/`doGenerate` keep the existing one-shot "final answer now" nudge
(`needsFinalNudge` / `foldEmptyFinal`). If a candidate emits NOTHING usable (no text, no tool
call, no foldable reasoning), it is treated as a quality failure and the chain advances to the
next candidate instead of ending the turn empty. If a candidate already streamed reasoning but
no answer, the nudge/fold promotes that reasoning (switching mid-reasoning would corrupt the
output) — so quality-switch is clean only for silent candidates.

### Guarantee
A single model failing never fails the whole turn:
```
A failed → B → B failed → C → C success → same conversation continues
```
Model changes; context does not.
