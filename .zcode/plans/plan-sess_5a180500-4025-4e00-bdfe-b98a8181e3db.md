# Adopt the Cline SDK as the agent engine (in-process, no localhost server)

## Decision
Replace our custom AI-SDK agent loop (`src/agent/core/*`) with the official **Cline SDK** (`@cline/sdk`, Apache-2.0, v0.0.79, pinned). It runs fully in-process inside the VS Code extension host — no localhost URL, no ports, no subprocess — and is the only surveyed project that combines a complete agentic skeleton (loop, built-in file/terminal/browser tools, checkpoints, MCP, subagents, approvals) with pluggable multi-provider routing. We keep our webview UI and message protocol, follow Cline's agent workflow/toolset, and plug our existing Router in for auto-mode model routing.

## What stays
- Webview UI (`media/src`, ResultCard, Plan, TodoSheet, ModelPicker) and the message protocol (`src/messages.ts`, `src/shared/`).
- `ChatViewProvider` orchestration, approvals, transcript persistence, auto-continue.
- Router (`src/router/`), ~30 providers, catalog, MCP manager, edits subsystems.

## What gets replaced
The AI-SDK loop in `src/agent/core/*` (loop.ts, stepEngine.ts, planRunner.ts, routerProvider.ts, tools/, watchdog.ts). `src/agent/agent.ts` stays as the public seam (`runAgentStream/runPlanStream/runAskStream`), reimplemented on Cline's `Agent`. This supersedes the AI-SDK-only policy from commit 9cad3c9 — the policy doc gets updated.

## Steps
1. `npm i @cline/sdk@0.0.79` (exact pin, pre-1.0); verify extension-host Node ≥22 (bump `engines.vscode` if needed); adjust esbuild externals.
2. **Router bridge** (`src/agent/core/cline/routerProvider.ts`): register a custom provider in `@cline/llms`' gateway delegating to `Router.route()` — analog of today's `core/routerProvider.ts`, preserving failover, cooldowns, key rotation, Smart Auto, session-sticky pins, pinnedModel/`'auto'`.
3. **Engine adapter** (`src/agent/core/cline/engine.ts`): implement `runTurn` via Cline `Agent` + `subscribe()` — map `assistant-text-delta`→`assistantChunk`, tool events→`toolStatus`, todos/plan→`todos`/`planProgress`, errors→`failoverNotice`/`engineStatus`. Use Cline's built-in tools, approvals (mapped to our approval UI), and Plan/Act modes for our plan/agent/ask modes. Reuse the existing `engineStatus`/`retryEngine` plumbing as the boot path.
4. Delete the old AI-SDK `streamText` loop and custom toolset; drop `ai`/`@ai-sdk/provider` deps if unused elsewhere.
5. Webview polish where Cline's event shapes differ (tool result cards, checkpoint/undo affordance).
6. Port e2e scripts to the new seam; add one e2e for Router failover through the Cline provider bridge; update docs (replace AI-SDK policy + simple-core reset notes with Cline-engine invariants).

## Risks
- 0.0.x API churn → pinned version + lockdown tests.
- Node ≥22 host requirement → `engines.vscode` bump.
- Our 22 custom tools (symbolGraph, fleet, deepSearch…) are dropped for Cline's toolset; critical ones can return later via `createTool`.

## Verification
- Clean esbuild bundle; e2e: pinned-model turn, auto-routing turn with forced failover, plan-mode turn, approval round-trip.
- Manual F5 run of a coding task in the webview; `lsof` confirms no listening port during a run.
